## 1. 组成与职责

```
server/wish_server.py     服务端（唯一后端）
server/panel.html         大屏面板 + 管理后台（单文件，零构建）

native/                   原生更新模块源码
deploy/                   systemd 单元 + 部署脚本
```

## 3. 架构与数据流

```
笔端 App ──HTTP/JSON──► wish_server.py ──► SQLite
   │  轮询 5s              │
   │                       └─SSE──► panel.html（实时热榜）
   │
   └─原生模块 updater：download → install → start（自动更新）
```

**为什么笔端是轮询而不是 SSE**：Falcon 环境没有 `EventSource`，笔端只能定时拉。
面板用 SSE 是为了"实时大屏"的效果。

**写操作为什么是 GET**：见第 8 节。

## 4. 数据模型（SQLite）

```sql
wishes(id, title, desc, category, nick, sn, votes,
       created_at, updated_at, deleted,
       claimed_by, claimed_at, claimed_voter,
       status)
votes(wish_id, voter, created_at)              -- 主键(wish_id, voter)，天然去重
claims(id, wish_id, nick, voter, sn, created_at, released_at)  -- 认领审计
client_logs(id, sn, client_id, version, level, msg, created_at)
meta(k, v)                                     -- 键值：目前存应用发布信息(release)
```

要点：

- `deleted=1` 为软删除（进回收站），`hard=1` 删除才会物理清除
- `votes` 表用 `(wish_id, voter)` 做主键，重复 +1 天然幂等，不需要额外判重
- `voter` 是稳定化标识：`sn:<设备号>` > `cid:<客户端ID>` > `ip:<地址>`
- `category` 取值 `app/feat/game/read/system/other`；`status` 取值 `open/doing/done/rejected`
- 旧库升级靠 `MIGRATIONS` 列表逐列 `ALTER TABLE`，新增字段不需要重建库

## 5. 关键设计决策（以及为什么）

| 决策 | 原因 |
|---|---|
| 服务端零依赖（标准库） | 目标机器只保证有 python3；避免 pip 与网络问题 |
| 面板单文件零构建 | 改完直接 scp 生效，不需要前端工具链 |
| 写操作走 GET + query | 平台 POST body 会丢（第 8 节） |
| 一人一票按 SN 去重 | 笔是共享设备时 SN 相同视为同一人，符合场景 |
| 认领要管理密码 | 认领是"我来做"的承诺，不该人人可点 |
| 内置输入法 | 系统输入法只对官方应用开放（第 8 节） |
| 预设愿望点选 | 让不打字也能完整表达诉求，降低笔上输入成本 |
| 状态由服务端管，客户端只读 | 避免客户端各自为政 |

## 6. 构建与发版

### 笔端构建

```bash
cd client
npm install                 # aiot-vue-cli + falcon-ui
npm run build:prod          # aiot-cli -c -q -p
# 产出 8001865309000101.<version>-rk.amr
```

版本号**两处**必须同步：`client/package.json` 的 `version`，以及
`client/src/services/updater.js` 的 `APP_VERSION`（笔端用它做更新比较）。
漏改会导致更新检测异常。

### 装机

```bash
adb push 8001865309000101.x.y.z.amr /userdisk/
adb shell miniapp_cli install /userdisk/8001865309000101.x.y.z.amr
```

### 发版（此后可自动更新）

1. 面板 → 管理 → **发布更新** → 上传 `.amr`
2. 填版本号（数字要大于当前）、说明，需要时勾「强制更新」
3. 发布

客户端下次启动会 `GET /app-update` 并弹窗。**首次**必须手动装一次带原生模块的包，
因为旧版本没有安装能力。

### 回滚

面板「发布更新」里把版本号改回旧版本并选旧包即可（客户端会认为有更新从而回退）；
极端情况直接 `adb install` 旧包。

## 7. 运维手册

```bash
systemctl status wishpool          # 状态
systemctl restart wishpool         # 重启
journalctl -u wishpool -n 100      # systemd 日志
tail -f /opt/wishpool/wish.log     # 应用日志
curl 127.0.0.1:17613/healthz       # 健康检查
```

- **改管理密码**：`echo '新密码' > /opt/wishpool/admin_pass.txt && systemctl restart wishpool`
  （笔端会缓存旧密码，改完后笔上首次认领会提示密码错误并重新输入）
- **备份**：`sqlite3 wish.db ".backup backups/wish-$(date +%F).db"`
- **清空业务数据**：删 `votes / claims / wishes / client_logs` 四张表内容
- **安装包**：放在 `PKG_DIR`（默认 `pkg/`），面板可直接上传

## 8. 平台限制与踩坑清单（最重要）

这部分是大量真机调试换来的，改动前务必先看。

### 8.1 网络

| 现象 | 真相 |
|---|---|
| POST 请求体为空 | 真机上原生 `http` 的 **POST body 会丢**，写操作必须走 `GET + query` |
| 响应解析成空字符串 | `resolve` 的值可能是 `{error, result}` **包装对象**，需要先解包 |
| JSON.parse 失败 | 有的固件把**响应头**一起返回，要按 `\r\n\r\n` 剥掉 |
| 解码出乱码 | 不能依赖 `escape()/decodeURIComponent()` 一定存在，`api.js` 里是手写 UTF-8 解码 |
| 回调不触发 | 原生 `http` 偶发不回调，必须自加看门狗超时（当前 14s） |
| 判为"离线"但网络通 | 有的接口响应**不带 `ok` 字段**，成功判定要用"能解析出 JSON 即成功"，别只认 `data.ok===true` |
| `downloadFile` 永不 resolve | 该固件上平台下载接口会挂住，下载必须走原生模块的 curl |

### 8.2 UI / CSS

| 限制 | 说明 |
|---|---|
| 只支持**单类名**选择器 | `.a .b`、`.a.b` 全部会被丢弃，必须写成独立类名（如 `.st-doing`） |
| 无 `border` / `box-shadow` 简写 | 只能用 `border-width` / `border-style` / `border-color` 分开写 |
| 文字必须在 `<text>` 里 | 直接写在 `<div>` 里不渲染 |
| `<div>` 不能滚动 | 滚动必须用 `<scroller>` |
| 无 `em/rem/pt`，`px` 不能省 | 尺寸单位只能用 `px/rpx/%/vw/vh` |
| `pointer-events` 不生效 | 不能用它屏蔽触控，只能在事件处理器里判 |
| 不支持 `v-bind:style` 对象语法 | 会黑屏；动态样式只能用 `v-bind:class` |
| 原生模块禁止静态 import | 静态 import 在求值前解析，缺 `.so` 时整页黑屏；必须动态 `require` + try/catch |

### 8.3 输入法

本机型固件**不对第三方应用开放系统输入法**，所以 App 内置了一套：

- `pinyin.js` + `pinyin-dict.js`：拼音候选（单字 / 词 / 前缀）
- 三种模式：ABC / 拼音 / 123
- 词库是万象拼音（CC-BY-4.0），约 20KB 单字表 + 词库

### 8.4 屏幕适配

设计基准 **960×266**（横屏超宽短屏）。`app.js` 里 `setViewPort(960)`，
横向用 `vw`、纵向用 `vh`；每个尺寸都写了 `px` 兜底 + `vw/vh` 覆盖两条声明。
逻辑高度由物理分辨率反算（`screen.js`），不要假设固定 266。

### 8.5 触控

`@touchstart` 会在手指落下的瞬间触发，用它做点击必然导致"滑动时误触"。
现方案：统一用 `@touchend` + 位移判定（`isTap` / `isTapSimple`）：
- 卡片：位移 > 14px 或按压 > 900ms 视为滑动
- 按钮：位移 > 14px 视为滑动

## 9. 排错手册

| 现象 | 定位手段 |
|---|---|
| 笔端一直显示离线 | 笔上点「日志」看时间线 → 点「上报日志」→ 面板后台 `GET /api/admin/logs?sn=` 查 |
| 面板实时不刷新 | 检查 Nginx 是否 `proxy_buffering off`；浏览器是否拦截 SSE |
| 认领报 401 | 笔端缓存的管理密码与服务端不一致，重新输入即可 |
| 更新下载失败 | 检查 `/pkg` 可访问；下载路径必须是**纯 ASCII** |
| 更新后页面白屏 | 大概率静态 import 了原生模块，或缺 `.so` |
| 某个按钮完全点不动 | 检查该元素的选择器是不是复合类名（被丢弃后样式/命中都异常） |

日志三层：

1. `console` —— Chrome / 真机调试直接看
2. `storage` KV —— 保留最近 220 条，重启不丢
3. `POST/GET /api/log` —— 上报到服务端，`GET /api/admin/logs` 查看

## 11. 交接清单（敏感信息不随仓库分发）

仓库里**不含**以下内容，接手后需单独索取或自行生成：

| 项 | 说明 |
|---|---|
| 服务器地址与端口 | 见 `client/src/services/api.js` 的 `ENDPOINTS`，仓库里是占位符 |

| 管理密码 | 服务器 `<部署目录>/admin_pass.txt`（权限 600），面板「管理」用 |
| 设备序列号 | 用于区分设备，不要写进代码 |
| 生产数据库 | 服务器 `<部署目录>/wish.db`，含真实用户愿望与日志 |

**建议**：接手后立刻轮换管理密码与 SSH 凭据，并在 `.gitignore` 之外确认
没有把 `admin_pass.txt` / `*.db` / `*.log` 提交进仓库。

## 13. 快速上手路线（给接手者）

1. 本地跑起服务端：`cd server && python3 wish_server.py`，打开 `http://127.0.0.1:17613/`
2. 面板点「管理」→ 用 `admin_pass.txt` 里的密码登录 → 试一遍改状态 / 删除 / 回收站
3. 装一次笔端包，点「日志」确认能连通
4. 读第 8 节，然后改一个小样式（比如把卡片高度 +4px），跑一次 `npm run build:prod` 熟悉构建
5. 用面板「发布更新」推一个 +0.0.1 的版本，验证笔端自动更新链路
